## Landed-design deviations from the original plan text (all recorded in ADR-0017)

1. **Host-side merge unwired; iteration is agent-side full re-emit.** Add. 21 said the
   host merges the agent patch then submits SetPageApp. Landed: `mergePageAppPatch`
   (`static/js/openui-lang/renderer.ts`) exists but has no production caller; the real
   loop is `GetPageApp` → agent re-emit → `SetPageApp` (OCC). ADR-0017 §"Server as
   validator+stamper" documents this; no `MergePageAppPatch` RPC exists.
2. **SetPageApp `lang` input field dropped** — server-stamped (v1: always
   `openui-lang`); matches the issue body, the plan's field list was stale.
3. **Page hash excludes `wiki.page_app_state`** (commit 923e770c) — the
   self-erasing-counter fix: state flushes must not remount the composed view.
   Regression-pinned in `page_app_hash_test.go`.
4. **RFC3339 stamp encoding** (fix f024dff8) — `wiki.page_app.updated_at` is an
   RFC3339 string, not `time.Time`: a `time.Time` value made the frontmatter indexer
   reject the whole page (observed live in e2e). Legacy `time.Time` values still parse.
5. **Guard reconciliation under composition** — an unconfirmed SetPageApp on a
   prose page **composes** (prose kept), so the Add-15 guard fires only on
   prose-clearing writes: SetPageApp WITH `confirm_replace_content=true` converts to
   app-alone (allowed), edit-path writes (UpdatePageContent/UpdateWholePage/
   CreatePage) that drop >10% of ≥1KB prose fail `FailedPrecondition`.
6. **ACL identity on page app reads/watches; identity attribution on all writes**
   (commit 663953cc) — page app reads honor `wiki.authorization`; ADR-0016 history
   records the real author/is_agent on page app writes.
7. **`confusion-page-app-*` eval rows are ×2, not ×3** — the third row
   (`-not-page-history`) targeted `GetPageAppLog`, which Addendum 13 removed from the
   service surface. Justified drop.
8. **Supporting infra committed beyond the plan's file map** (Phase D support, all
   disclosed): `e2e/build-runner.ts` (E2E_SKIP_BUILD opt-in), `e2e/playwright.config.ts`
   (fixed TLS port 18092 to avoid the A2A listener collision), `scripts/run_fe_tests.sh`
   (honor caller-provided CHROMIUM_BIN), `internal/bootstrap/server.go` +
   `transcoder_coverage_test.go` (service-registration parity for the two new services).
9. **Post-plan feedback wave + pruner (user-directed beyond Phase E, 2026-10-24)**:
   the Artifact→Page App full rename (6ee92570/0ef2a831); suspension-recovery backoff
   (18dccdbe); design-system/responsive work (2418850e/7d6a2d24); a startup-system-page
   **pruner** with `wikipage.PageLister` + `Site.ListAllPageIdentifiers` (bb45419e,
   d28bc114 — munged keep-set so hyphenated identifiers survive; TDD); live-server
   trash-trim of the retired `help_artifacts_lang` page; reactive-prop render fix
   (998448b2); the `$value` step-scope fix for form-control onChange (515be84e — NEW
   language semantic: inside an `Input`/`Select` onChange step the control's typed
   value is visible as `$value`); help common-patterns + missing-component
   feature-request guidance (22f8ff02/bc5d613c); e2e identifier repairs (be92a414).
   All user-steered in-session; recorded here as the plan amendment.

## Known limitations (deliberate, documented — not oversight)

- **Server-side `ReplaceFrontmatter` can still hit an page app page** (the disable is client-side at the dialog level). Reserved `wiki.*` subtrees are protected wholesale by the frontmatter registry; user-key races are the residual exposure. Server-side guard is a future hardening (would need GetFrontmatter/ReplaceFrontmatter to check for `wiki.page_app`).
- **W3's agent-reply half** rides the same SetPageApp→Watch hot-swap path as W2's iteration (covered); the e2e asserts the chat DOOR (SendMessage wire payload) — full loop with a live agent needs a pool, out of e2e scope.
- **MergeState arrays union** — an app can never remove a list item without DeleteState; the merge policy (RFC 7386-style replace) is a possible v2 change recorded in the proto text.
- **State flushes snapshot page history** (one version per flush; ADR-0016 capture is content-based). Debounced/host-side throttle is future work if history volume matters; the hash exclusion already prevents the remount loop.
- **`ClearPageApp` leaves `wiki.page_app_state` orphaned** (by design: state is cross-app durable under a reserved subtree; a re-authored app starts from the prior state rather than silently losing it). A `DeleteState` after clear is the explicit reset.
