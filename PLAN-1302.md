## Design decisions (locked)

1. **Tabs are state-driven**: `Tabs($active, panes, labels)` binds the active pane
   **label key** (string, not index — see PR3 spec) to `$state`, matching the Countdown
   program-owned `running` gate pattern. Programs can auto-switch panes
   (Countdown `onComplete` → `@Set($pane, "Cooldown")`).
2. **No Portal primitive**. Dialog wraps the native `<dialog>` element (top-layer is
   already standard). Popover/Tooltip compose on the existing shared `<menu-popover>`
   primitive from #1300 (viewport-aware flip, outside-click/Escape close — placement
   logic exists exactly once).
3. **Toast is an action step (`@Toast(message, kind?)`), not a component** — transient
   feedback belongs in action flows, like `@Beep`.
4. **First PR is the full P1 layout batch**: Grid + Divider + SectionHeader + Card
   variants, in one PR with TDD + help docs.

## PR1 — P1 Layout batch (`library.ts` + `page-app-design-system.ts`)

### Components

1. **Grid**: props in order `(children, cols, gap?)` — **children first**, matching every
   other container in the library (`Stack(children, direction?, gap?)` at
   `library.ts:586-591`, `Card(title, children, variant?)` at :610-615). A program writes
   `Grid([Stack(...), Stack(...)], 2, "lg")`; the natural `Grid([...], 2)` binds cleanly.
   The earlier `(cols, gap?, children?)` order was rejected in review: a second positional
   array would land in `gap` and fail validation, dropping the whole Grid. `cols`:
   `z.union([z.number().int(), z.literal('sidebar')])`, `gap`: existing
   `sm|md|lg|xl|css-string` token union (reuse Stack's). Renders
   `<div class="wiki-page-app-grid" data-cols=…>` —
   numeric N → `grid-template-columns: repeat(N, 1fr)` (accept 2 and 3; validate range);
   `sidebar` → `240px 1fr`;
   - Grids collapse to one column under the design system's existing 520px media query
  (mobile-first per mockups).
   - Children that are `Span(n, [...])` wrappers set `grid-column: span n` via a
     attribute rendered as inline `grid-column: span n`; n is enum-validated at parse
     time (1|2|3 only, matching common grid col counts), and collapses on mobile.
     Span's props stay **count-first** (`Span(n, children)`) — different from Grid's
     children-first — because `n` is mandatory and small (enum-validated so an
     accidental `[children, n]` call fails validation loudly instead of silently
     mis-binding); `n: z.literal([1, 2, 3])` (enum leaf — lang-core validates it,
     out-of-range n is a parse-time type-mismatch, matching cols enforcement).
     Documented in both component descriptions so the asymmetry is visible at
     authoring time.
2. **Span**: `Span(n, children)` — count-first per above; layout wrapper consumed by
   Grid (also valid in the children union for parser completeness; rendering outside a
   Grid falls back to a Stack block).
3. **Divider**: no props. `<hr class="wiki-page-app-divider">` — `border-top: 1px solid var(--color-border-subtle)`.
4. **SectionHeader**: props `(title, trailing?)` — flex row: title, hairline rule
   (flex:1), then optional trailing child (e.g. a `Badge`, a count `Text`).
5. **Card variants**: `variant` prop appended AFTER `children` so positional
   `Card("title", [...])` is untouched — `z.enum(['default','elevated','outlined','filled','accent']).optional()`.
   CSS (`data-variant` attr on the existing `.wiki-page-app-card`):
   - `elevated`: stronger shadow, no border.
   - `outlined`: flat, `--color-border-strong`, no shadow.
   - `filled`: `--color-surface-sunken` bg, no border/shadow.

- `accent`: accent-tinted gradient wash over `--color-surface-elevated`
    (uses new opaque `--color-accent-bg` token — see New design tokens below).
 Card `image`/`minHeight` props were DROPPED from PR1 in review (unsanitized
   `url('${image}')` interpolation = CSS injection; defer to PR6 imagery with an
   allowlist + unit-correct `minHeightPx`).

### New design tokens (`default.css`, both light+dark, keep CRLF)

- `--color-accent-bg` / `--color-accent-text` — opaque accent pair, completing the
  existing semantic family (`--color-success-bg/-text` :50-51, `--color-error-bg/-text`
  :53-54, `--color-warning-bg/-text` :56-57, light+dark :114-122). Light: `#e9f2ff`
  bg with `#0d5dd7` (deviation from the originally locked `#4078c0`, which
  computes ≈4.0:1 on that bg — fails the plan's own G6 AA guard; `#0d5dd7` is 5.22:1); dark: `#16273d` bg with
  `--color-text-link #6ea8fe`. Opaque 6-digit hex is REQUIRED —
  `internal/design/design_test.go:40` (`tokenValues`) asserts `#`-prefix and rgba would
  fail the guard; alpha compositing over surfaces would also complicate every consumer.
  An earlier `--color-accent-soft` rgba proposal was rejected in review on exactly this
  ground. Guard extended (G6) to assert ≥4.5:1 for `--color-accent-text` on
  `--color-accent-bg` in both modes — same trivially-satisfiable pattern as the
  existing semantic pairs. PR5 `Badge` kinds reuse these pairs (no parallel `*-soft`
  family).

## Later PRs (each follows the same TDD + docs pattern — detailed specs when opened)

- **PR2 Dialog + @Toast**: `Dialog(title, children, open, onConfirm?)` wrapping native
  `<dialog>` — `open` is reactive (`markReactive` like `InputSchema.shape.value`,
  `library.ts:366`), applied in `updated()` via `showModal()`/`close()` so the DOM and
  `$open` never diverge. Native Esc/backdrop-close fires the `close` event without
  touching program state, so the component dispatches an `onClose` plan on that event
  (program authors wire `onClose → @Set($open, false)`) — otherwise a persisted
  `@Set`-flushed `$open = true` would re-open a dialog the user dismissed on reload.
  Positional order: `title`, `children`, `open`, `onConfirm?`. `::backdrop` uses
  `--color-surface-overlay`; Esc and focus trapping come free from the native element
  (no custom focus-trap). Cancel button closes without running `onConfirm` (fires only
  `onClose`). `@Toast(message, kind?)` action step rendering theme-styled transient
  surface (reuse design-system classes; aria-live polite).
- **PR3 Tabs + Accordion**: `Tabs($active, panes, labels)` state-driven per decision 1;
  `$active` is `markReactive` (mandatory — without it `@Set($pane, 2)` can't re-render
  the pane). Pane identifier is the **string label key** (not an index — indices break
  on reorder; duplicate labels rejected at parse time). `$active` flushes to persisted
  state, so the active tab survives reload; unknown/stale labels fall back to pane 0.
  `Accordion([[title, children], ...])` on native `<details>`. Tabs machinery builds on
  the dialog/a11y groundwork.
- **PR4 Form controls**: `Switch`, `Checkbox`, `RadioGroup`, `Slider`, `NumberInput`, `Textarea`.
- **PR5 Polish batch**: `Badge` (kinds using `--color-*-soft` tokens), `Icon` (inline-SVG
  curated set), `List`, `Skeleton` (Query loading states).
- **PR6 Imagery**: `Image(fileHash|src, alt?, fit?, aspectRatio?)` over the wiki file-upload
  surface; Card `image:`/`minHeight:` props for hero cards. No external CDNs.
- **PR7 Graphics tier 1 (opt-in)**: `Sketch` declarative canvas/SVG primitives — shapes,
  gradients, particles; `$state`-fed animation params. No arbitrary JS. Lottie/regl tiers
  deferred until an app demands them; three.js only as last resort.

## TDD execution order (PR1; each: Red → Green)

G1 **Grid schema/render**: `Grid([...], 2, "lg")` renders `data-cols="2"` + grid css;
   `Grid([...], "sidebar")` → 240px/1fr template; invalid cols rejected; gap tokens map
   like Stack's; children-first safety — `Grid([...], 2)` binds cleanly with no gap.
G2 **Span**: `Span(2, [...])` inside Grid spans 2 columns; `Span(0|4|5|…)` is a parse-time
   type-mismatch (enum-validated n, mirroring Grid cols); collapses on mobile; outside
   Grid renders as block.
G3 **Divider + SectionHeader**: no-args Divider renders `<hr>`; `SectionHeader("Workout", Badge(...))`
   renders title + rule + trailing slot.
G4 **Card variants**: each variant emits `data-variant`; positional `Card("t", [...])`
   unchanged; variant-last prop order parse tests (mirror PR #1298's G2 pattern).
G5 **Card image prop**: DEFERRED to PR6 (imagery) — see the Card variants section; the
   `image`/`minHeight` props were dropped in review (unsanitized url() interpolation).
   No PR1 test/implementation for this gate.
G6 **Accent tokens + contrast guard**: extend `internal/design/design_test.go` to
   assert `--color-accent-text` on `--color-accent-bg` ≥4.5:1 in light + dark —
   opaque hex only (`tokenValues` asserts `#`-prefix at design_test.go:40).
G7 **Version bump**: tests pin `wiki-core@3` (JS + Go literals).
G8 **Docs ride-along**: `help_page_apps.md` — new components, updated missing-list,
   `wiki-core@3`; ADR-0017 vocabulary note; wiki system prompt auto-includes new
   components via `generateWikiSystemPrompt()`.
