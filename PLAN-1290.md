# PLAN-1290: GetPageAgent maps missing page to NotFound

Issue: https://github.com/brendanjerwin/simple_wiki/issues/1290
Branch: `brendanjerwin/agentinventoryservice.getpageagent-maps-missing`

## Finding

`GetPageAgent` on a nonexistent page returns `codes.Internal` and leaks the raw
storage error (`read frontmatter for "__nonexistent_probe__": file does not
exist`) to the chat panel.

## Root cause

- `internal/grpc/api/v1/agent_inventory.go:81` wraps every `GetBinding` error
  as `codes.Internal`, unconditionally.
- The store wraps the pagestore error with `fmt.Errorf(errReadFrontmatterFmt, …)`
  using `%w`, and pagestore's `Reader.ReadFrontMatter` documents
  `os.ErrNotExist` as its missing-page sentinel. **Gotcha:** plain
  `os.IsNotExist` does NOT unwrap `*fmt.wrapError` — the branch must use
  `errors.Is(err, os.ErrNotExist)`.

## Design decision

Follow the repo precedent in `frontmatter.go` / `page_management.go`:
not-exist → `codes.NotFound` with `pageNotFoundErrFmt` ("page not found: %s");
everything else stays `codes.Internal` ("get page agent: %v"). Do NOT touch the
already-correct `InvalidArgument` (empty page) or `FailedPrecondition`
(nil inventory/store) branches.
